Up and running in 2 minutes

Install the SDK, add one config line, and every function in your app is tracked — no manual wrapping.

1

Install the SDK

npm install @prodscope/sdk-browser

For Node/Express apps: npm install @prodscope/sdk-node

2

Add the Vite plugin

import { prodscope } from "@prodscope/sdk-browser/vite";

export default defineConfig({
  plugins: [
    prodscope({ apiKey: process.env.PRODSCOPE_API_KEY }),
  ],
});

The Vite plugin instruments every exported function at build time with file:line metadata.

3

Init in your app entry

import { init } from "@prodscope/sdk-browser";

init({
  projectId: "my-app",
  apiKey: import.meta.env.VITE_PRODSCOPE_API_KEY,
});

Install the VS Code extension and see live production data on every function.

SDK Reference

Full setup for browser apps, Node.js backends, and Claude Code integration.

@prodscope/sdk-browser
npm install @prodscope/sdk-browser
1. Add the Vite plugin — instruments every exported function automatically
// vite.config.ts
import { defineConfig } from "vite";
import { prodscope } from "@prodscope/sdk-browser/vite";

export default defineConfig({
  plugins: [
    prodscope({
      apiKey: process.env.PRODSCOPE_API_KEY,
    }),
  ],
});
2. Initialize in your app entry point
// main.tsx / index.tsx
import { init } from "@prodscope/sdk-browser";

init({
  projectId: "my-app",
  apiKey: import.meta.env.VITE_PRODSCOPE_API_KEY,
  // Optional:
  environment: import.meta.env.MODE,   // "production" | "staging"
  release: import.meta.env.VITE_GIT_SHA,
});
3. Set your env variable
# .env.production
VITE_PRODSCOPE_API_KEY=ps_live_xxxxxxxxxxxx
What gets tracked automatically
✓ Every exported function — call count, p50/p99 latency, error rate
✓ Fetch / XHR requests — URL, status, duration
✓ Unhandled errors — stack trace mapped to file:line
✓ Session data — which users hit which functions and how often
✓ Click interactions — linked to the function that handled them
@prodscope/sdk-node
npm install @prodscope/sdk-node
1. Initialize at app startup
// index.ts — must be the very first import
import { init } from "@prodscope/sdk-node";

init({
  projectId: "my-api",
  apiKey: process.env.PRODSCOPE_API_KEY,
  environment: process.env.NODE_ENV,
  release: process.env.GIT_SHA,        // optional, for deploy comparison
});
2. Add Express middleware — tracks every route with latency and errors
import express from "express";
import { expressMiddleware } from "@prodscope/sdk-node/express";

const app = express();
app.use(expressMiddleware());   // add before your routes
3. Prisma middleware — tracks every query with duration and model
import { PrismaClient } from "@prisma/client";
import { prismaMiddleware } from "@prodscope/sdk-node/prisma";

const prisma = new PrismaClient();
prisma.$use(prismaMiddleware());
4. pg middleware — tracks raw SQL queries
import { Pool } from "pg";
import { pgMiddleware } from "@prodscope/sdk-node/pg";

const pool = new Pool({ connectionString: process.env.DATABASE_URL });
pgMiddleware(pool);              // wraps the pool in-place
What gets tracked automatically
✓ Every Express route — method, path, status code, latency
✓ Prisma queries — model, action, duration, slow query detection
✓ pg queries — SQL text (sanitized), duration, error stack
✓ Unhandled exceptions and rejected promises
✓ All mapped to file:line so VS Code shows them inline
@prodscope/mcp-server
npm install -g @prodscope/mcp-server
1. Add to Claude Code's MCP config
// ~/.claude/settings.json
{
  "mcpServers": {
    "prodscope": {
      "command": "prodscope-mcp",
      "env": {
        "PRODSCOPE_API_KEY": "ps_live_xxxxxxxxxxxx",
        "PRODSCOPE_PROJECT_ID": "my-app"
      }
    }
  }
}
2. Or use npx — no global install needed
{
  "mcpServers": {
    "prodscope": {
      "command": "npx",
      "args": ["-y", "@prodscope/mcp-server"],
      "env": {
        "PRODSCOPE_API_KEY": "ps_live_xxxxxxxxxxxx",
        "PRODSCOPE_PROJECT_ID": "my-app"
      }
    }
  }
}

Available MCP tools
✓ get_function_stats — call count, latency percentiles, error rate per function
✓ get_errors_at_line — errors at a specific file:line with stack traces
✓ get_slow_queries — slowest DB queries with duration and frequency
✓ get_hot_paths — most-called user journeys through your functions
✓ compare_deploys — diff two deploys by latency, errors, and call patterns
✓ get_live_sessions — active sessions and what functions they're hitting
✓ get_ai_insight — Claude-generated analysis of what's wrong and why
