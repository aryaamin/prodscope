ai insight fetchProducts · just now
root cause

Safari 17 ships Array.at() behind a flag. The cache key builder on line 16 calls category.at(-1), returning undefined — which invalidates the cache and sends every Safari user to the failing network path on line 18.

impact

14 errors in last 6h, 100% Safari/iOS. Affects 8% of your sessions. Trending up since Tuesday’s deploy (a3f9c2).

fix

Replace category.at(-1) with category.slice(-1) or ship the polyfill from PR #221. Verify with verify_fix after deploy.

> the problem

Developers ship code they can’t see.

The moment your code leaves your laptop, it disappears. What runs in production is a black box — and the tools we’ve been handed weren’t built for the person writing the code.

problem

You’re debugging blind.

  • 87% of production bugs are reported by users, not caught by developers.
  • The average engineer spends 13 hours/week reproducing issues they can’t see.
  • Every function you write runs invisibly — you don’t know which ones are slow, failing, or never called.
  • When something breaks, you grep logs, ping teammates, and guess.

“Works on my machine” is the industry’s $300B/year excuse.

the gap

APM was built for ops, not coders.

  • Datadog, New Relic, Dynatrace — $500 to $5,000/mo dashboards built for SRE teams.
  • Sentry shows errors but stops at the stack trace. No latency. No user reach. No fix.
  • Logs & traces live in a separate app, separate auth, separate mental model from the code.
  • Nothing connects production telemetry to the file:line a developer is actually editing.

Developers don’t need another dashboard. They need the answer, on the line, in the editor.

solution

ProdScope brings production to your cursor.

  • Every function annotated inline in VS Code: calls, p50/p99, error rate, % of users reached.
  • AI that reads your telemetry and tells you exactly which line to fix — and why.
  • MCP server so Claude, Cursor, and any AI coding agent debugs with real production data, not guesses.
  • 2-minute setup. One Vite plugin, one init call. Works with React, Next.js, Express, Prisma, Cloudflare Workers.

The first observability tool that actually makes you a better coder.

> introducing remedy

Prodscope detects the bug.
Remedy fixes it.

When errors cross a threshold, Remedy wakes up, reads the source, runs an AI agent in a sandboxed clone of your repo, and opens a draft PR — with a Slack notification and email. Zero human triage required.

coming soon
01

Error threshold crossed

Remedy watches ClickHouse for error signatures that spike past your threshold — 5+ occurrences / hour by default. It deduplicates on a 24h cooldown so the same error never spawns two PRs.

02

Agent spins up

Claude Agent SDK launches in a sandboxed worktree of your repo. It reads the offending file:line, the full stack traces, function stats, and the existing AI insight — then diagnoses the root cause.

03

Minimal fix applied

The agent edits only what's broken — no refactors, no scope creep. If it can't determine a safe fix from the evidence alone, it makes no changes and explains why. Surgical or nothing.

04

Draft PR opened

Remedy pushes a branch, opens a draft PR with the full diagnosis, stack traces, and agent reasoning as the body. Every auto-fix stays a draft — a human merges, never Remedy.

05

Slack + email notification

Your team gets a Slack Block Kit message with the PR link, error count, affected sessions, and the agent's one-sentence diagnosis. Optional email notification per project. No pager noise — just context.
